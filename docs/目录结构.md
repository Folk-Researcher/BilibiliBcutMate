一个清晰、合理的目录结构对 Python 项目的可维护性、可扩展性、团队协作和后期部署都至关重要。下面给出一份“开箱即用”的通用模板，并逐层说明每个文件/文件夹的职责、常见变种以及配套工具链（虚拟环境、打包、CI、文档等）。你可以直接复制使用，也可以按需裁剪。

--------------------------------------------------
1. 最小可运行模板（Single-package）
myproject/
├── src/                       # 1. 源码根目录（推荐用 src 布局，避免测试时 import 到本地脏包）
│   └── mypkg/                 # 2. 主包（与项目名保持一致，方便 pip install -e .）
│       ├── __init__.py
│       ├── cli.py             # 3. 可选：命令行入口（ Typer / Click / argparse ）
│       ├── core.py
│       └── utils.py
├── tests/                     # 4. 单元测试 & 集成测试（pytest 默认发现规则）
│   ├── __init__.py
│   ├── conftest.py            # 5. pytest 共享 fixture / hook
│   └── test_core.py
├── docs/                      # 6. Sphinx / MkDocs 文档源文件
│   ├── conf.py
│   └── index.rst
├── .github/                   # 7. GitHub Actions 工作流
│   └── workflows
│       └── ci.yml
├── scripts/                   # 8. 一次性脚本、数据迁移、调试工具（不随包发布）
│   └── seed_data.py
├── .gitignore
├── README.md
├── LICENSE
├── pyproject.toml             # 9. 现代 Python 打包配置（PEP 518/621）
└── requirements-dev.txt       # 10. 开发阶段额外依赖（lint、test、docs）

--------------------------------------------------
2. 为什么推荐 src/ 布局
• 防止“本地包阴影”：如果直接在根目录放 mypkg/，当你运行 pytest 时，Python 会把当前目录加入 sys.path，导致你真正安装到 site-packages 里的旧版本被遮蔽，测试的是本地代码，而不是用户装到的版本。  
• 与 tox / nox / CI 环境行为一致：这些工具总是在隔离环境里 pip install 你的包，src 布局保证测试的是“安装后”的制品。  
• 官方 PyPA 示例、PyScaffold、Hatch、Poetry 均默认或支持 src 布局。

--------------------------------------------------
3. pyproject.toml 最小示例
[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[project]
name = "mypkg"
version = "0.1.0"
description = "One line description"
readme = "README.md"
requires-python = ">=3.9"
dependencies = [
    "requests>=2.31",
]

[project.optional-dependencies]
dev = [
    "pytest>=7",
    "black",
    "ruff",
    "mypy",
]

[project.scripts]
mypkg = "mypkg.cli:main"   # pip install 后自动生成 mypkg 命令

4. 测试、风格、类型检查一键脚本
# Makefile 或 tox.ini / noxfile.py 均可
.PHONY: lint test
lint:
	ruff check src tests
	mypy src
test:
	pytest -q --cov=src --cov-report=term-missing

5. 常见扩展场景
1) 多包 Monorepo  
repo/
├── libs/
│   ├── lib-a/
│   │   └── pyproject.toml
│   └── lib-b/
├── apps/
│   └── web/
│       └── pyproject.toml
└── .github/workflows/
    └── ci.yml               # 使用 matrix 分别检测每个子包

2) 带数据文件 / 二进制轮子  
mypkg/
├── pyproject.toml
└── src/mypkg/
    ├── data/
    │   └── words.txt
    └── _internal.py
# pyproject.toml 加
[tool.setuptools.package-data]
mypkg = ["data/*.txt"]

3) Cython / Rust 扩展  
├── src/mypkg/
│   ├── _fast.pyx
│   └── __init__.py
├── setup.py                 # 仍需保留，用于构建扩展
└── pyproject.toml

6. 目录速查表（可复制做 checklist）
[ ] 源码：src/mypkg/  
[ ] 测试：tests/ + pytest.ini / conftest.py  
[ ] 文档：docs/ + Sphinx autodoc  
[ ] 打包：pyproject.toml（PEP 621）  
[ ] 版本：git tag + 自动推 PyPI（GitHub Release）  
[ ] 代码风格：black + ruff + mypy  
[ ] CI：GitHub Actions matrix（3.9/3.10/3.11/3.12）  
[ ] 依赖锁：requirements-dev.txt 或 pip-tools/poetry lock  
[ ] 入口脚本：project.scripts / console_scripts  
[ ] LICENSE & README.md & CHANGELOG.md

--------------------------------------------------
7. 一句话总结
“把源码放进 src/，把配置收进 pyproject.toml，把测试、文档、脚本、CI 各归其位，你就拥有了社区公认、工具链零成本接入的现代 Python 项目骨架。”
